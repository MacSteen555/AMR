# Insights Reports Redesign

## Overview

Redesign the AI-powered reports feature to generate a single user-chosen time period per run, add previous-period comparison, introduce a distinct annual report format, and rewrite prompts for plain language and confidence-calibrated output.

---

## 1. Generation Flow

**Current**: User clicks Generate -> 4 reports created (30d/90d/6m/1y) -> 3 credits.

**New**: User clicks Generate -> period picker (30d / 90d / 6m / 1y) -> 1 report created for selected period -> variable credit cost.

### Credit Cost by Period

| Period | Credits |
|--------|---------|
| 30d    | 3       |
| 90d    | 4       |
| 6m     | 7       |
| 1y     | 10      |

### API Changes

POST `/api/teams/[teamId]/insights/run` accepts a required `period_window` param. Runs a single `insightsRun()` call instead of four parallel calls.

### Data Fetching

The API fetches 2x the selected window for 30d/90d/6m to enable previous-period comparison:

| Period | Reviews Fetched     | Split                              |
|--------|--------------------|------------------------------------|
| 30d    | 60 days            | Current 30d + Previous 30d         |
| 90d    | 180 days           | Current 90d + Previous 90d         |
| 6m     | 12 months          | Current 6m + Previous 6m           |
| 1y     | 1 year only        | No comparison (yearly roundup)     |

### Report Library

List view sorted by `generated_at` DESC with columns:
- Date generated
- Period covered (e.g. "Last 30 Days")
- Scope (team name or location name)
- Generated by (user name)

## 2. Output Schema (30d / 90d / 6m Reports)

These three share the same schema. Depth scales based on review count.

```typescript
interface StandardReportData {
  // --- Comparison Block (top of report, the "so what?") ---
  comparison: {
    currentAvgRating: number
    previousAvgRating: number
    currentReviewCount: number
    previousReviewCount: number
    currentSentiment: number       // 0-100
    previousSentiment: number      // 0-100
    headline: string               // e.g. "Ratings up, but review volume dropped 30%"
    keyDeltas: Array<{
      metric: string
      direction: 'up' | 'down' | 'flat'
      description: string
    }>                             // 2-4 most important changes
  }

  // --- Core Insights ---
  overallSentiment: number         // 0-100
  momentumScore: number            // -10 to +10
  executiveSummary: string
  ratingTrend: 'improving' | 'declining' | 'stable'
  topActionItem: { title: string; description: string }

  keyStrengths: Array<{
    theme: string
    description: string
    mentionCount: number
    exampleQuote?: string
  }>

  keyWeaknesses: Array<{
    theme: string
    description: string
    mentionCount: number
    severity: 'low' | 'medium' | 'high'
    exampleQuote?: string
  }>

  // --- 30d only ---
  emergingTopics?: Array<{
    topic: string
    sentiment: 'positive' | 'negative' | 'mixed'
    description: string
    previousMentions: number
    currentMentions: number
  }>

  // --- Risk & Action ---
  riskAlerts: Array<{
    title: string
    description: string
    urgency: 'low' | 'medium' | 'high'
  }>

  recommendations: Array<{
    title: string
    description: string
    impact: 'low' | 'medium' | 'high'
    effort: 'low' | 'medium' | 'high'
    category: 'service' | 'staff' | 'operations' | 'marketing' | 'product'
  }>

  // --- Customer Voices ---
  notableQuotes: Array<{
    quote: string
    rating: number
    sentiment: 'positive' | 'negative'
    theme: string
  }>
}
```

### Removed from current schema

- `customerPersona` -- owners know their customers already
- `responseStrategy` -- generic advice, not actionable
- `ratingTrendDescription` -- redundant with the comparison block

### Added

- `comparison` block with previous-period deltas
- `emergingTopics` now includes `previousMentions` / `currentMentions` for real comparison (30d only)

## 3. Output Schema (1-Year Annual Report)

Distinct structure. Narrative, visual, polished annual report with dashboard elements.

```typescript
interface AnnualReportData {
  // --- Year in Numbers (hero banner) ---
  yearInNumbers: {
    totalReviews: number
    averageRating: number
    totalResponses: number
    responseRate: number
    bestMonth: { month: string; avgRating: number; reviewCount: number }
    worstMonth: { month: string; avgRating: number; reviewCount: number }
    fiveStarPercentage: number
  }

  // --- The Year's Story (narrative arc) ---
  yearStory: string                // 2-3 paragraphs, the arc of the year

  // --- Monthly Timeline (feeds chart + annotations) ---
  monthlyTimeline: Array<{
    month: string                  // "2025-04"
    avgRating: number
    reviewCount: number
    annotation: string | null      // e.g. "Ratings jumped, new menu launched"
  }>

  // --- Highlights & Lowlights ---
  highlights: Array<{
    title: string
    description: string
    quote: string | null
  }>

  lowlights: Array<{
    title: string
    description: string
    quote: string | null
  }>

  // --- Enduring Patterns ---
  keyStrengths: Array<{
    theme: string
    description: string
    mentionCount: number
    exampleQuote?: string
  }>

  keyWeaknesses: Array<{
    theme: string
    description: string
    mentionCount: number
    severity: 'low' | 'medium' | 'high'
    exampleQuote?: string
  }>

  // --- Strategic Priorities for Next Year ---
  recommendations: Array<{
    title: string
    description: string
    impact: 'low' | 'medium' | 'high'
    effort: 'low' | 'medium' | 'high'
    category: 'service' | 'staff' | 'operations' | 'marketing' | 'product'
  }>

  // --- Customer Voices of the Year ---
  notableQuotes: Array<{
    quote: string
    rating: number
    sentiment: 'positive' | 'negative'
    theme: string
  }>
}
```

### Key differences from standard reports

- `yearInNumbers` replaces the comparison block (no previous year, just this year's stats)
- `yearStory` is a narrative arc, not a dry executive summary
- `monthlyTimeline` feeds a line chart with annotation callouts on significant shifts
- `highlights` / `lowlights` replace `riskAlerts` (retrospective framing, not urgent alerts)
- Recommendations framed as "next year's priorities"

### UI treatment

- More whitespace, larger typography for hero numbers
- Monthly timeline rendered as a line chart with annotation markers
- Pull quotes styled larger
- Overall feel: polished annual report document with dashboard elements woven in

## 4. Prompt Strategy

### 4a. Confidence Calibration by Review Count

Added to every prompt as a hard rule:

- **< 10 reviews**: Short report. Summary, strengths, weaknesses, 2-3 recommendations max. No trend claims. Acknowledge limited data directly: "Based on 6 reviews, here's what stands out."
- **10-50 reviews**: Standard depth. All sections populated, but descriptions stay to 1-2 sentences each. Trends stated with appropriate hedging.
- **50+ reviews**: Full depth. Richer analysis, more items per section, confident claims.

### 4b. Voice and Tone

Baked into every system prompt:

- Write like a sharp friend who runs a business, not a consultant.
- Second person: "you" and "your."
- Short sentences. No filler. No jargon.
- If a stat is trivial (e.g., 5.0 to 4.89 on 18 reviews), say so. Don't manufacture drama.
- Every sentence should make the owner feel smarter or prompt them to do something. If it doesn't, cut it.

### 4c. Period-Specific Framing

- **30d**: "What happened this month and what changed vs last month." Tactical. Do-this-week actions.
- **90d**: "What patterns are forming this quarter vs last quarter." Operational. Do-this-month actions.
- **6m**: "Are you making progress? What should you invest in next quarter." Strategic.
- **1y**: "The story of your year." Narrative. Next year's priorities.

### 4d. Previous-Period Comparison Instructions (30d/90d/6m only)

The prompt receives both current and previous period reviews, clearly labeled:

```
-- CURRENT PERIOD (Feb 9 - Mar 10) --
1. [5/5] [2026-03-08] "Amazing automation setup..."
...

-- PREVIOUS PERIOD (Jan 10 - Feb 8) --
1. [4/5] [2026-01-15] "Good service but slow..."
...
```

Instructions for the AI:
- Compute the comparison block first. This anchors the whole report.
- Every strength/weakness should note whether it's new, growing, shrinking, or persistent vs the previous period.
- Don't flag a "decline" unless it's meaningful relative to sample size.

## 5. Emerging Topics (30d Only)

The AI compares topics across both 30-day windows and returns mention counts for each period. The frontend derives the badge:

| Condition                                    | Badge    |
|----------------------------------------------|----------|
| `previousMentions: 0, currentMentions: 3+`  | **NEW**  |
| `currentMentions > previousMentions`         | **RISING** |
| `currentMentions < previousMentions`         | **FADING** |
| Roughly equal                                | **STEADY** |

## 6. Summary of Changes

| Aspect              | Current                                | New                                                        |
|----------------------|----------------------------------------|------------------------------------------------------------|
| Generation           | All 4 periods at once, 3 credits       | Single period chosen by user, 3/4/7/10 credits             |
| Previous period      | None (splits current period in half)   | Fetches 2x window for 30d/90d/6m, real comparison          |
| Comparison block     | Doesn't exist                          | Top of report with key deltas and headline                 |
| Emerging topics      | All periods, no baseline               | 30d only, with previous/current mention counts             |
| 1-year report        | Same schema as others                  | Distinct annual report schema: narrative, timeline, highlights |
| Removed sections     | --                                     | `customerPersona`, `responseStrategy`                      |
| Confidence scaling   | None (fills every section regardless)  | < 10 / 10-50 / 50+ reviews scales depth                   |
| Voice                | Consultant tone, dense paragraphs      | Direct, plain language, second person, pithy               |
